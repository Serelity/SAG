# 03 - 模型配置说明

当前阶段可以暂时跳过 LLM API 配置。RAGFlow 的登录账号是本地账号，建议保留；模型 API 是外部供应商能力，没有合适接口时可以先不配置。

## 为什么 RAGFlow 提示必须配置模型

创建知识库、解析文档和进行问答时，RAGFlow 需要两类模型：

| 模型类型 | 作用 |
| --- | --- |
| LLM / Chat | 根据检索到的内容生成回答 |
| Embedding | 把文档片段和用户问题转成向量，用于相似度检索 |

因此只配置 LLM 不够，只配置 Embedding 也不够。完整 RAG 闭环需要两者都可用。

## OpenAI-Compatible 需要什么接口

从当前 RAGFlow `v0.26.4` 源码看，OpenAI-Compatible 主要使用 OpenAI SDK 的两个接口：

```text
chat.completions.create(...)
embeddings.create(...)
```

对应接口通常是：

```text
/v1/chat/completions
/v1/embeddings
```

所以供应商文档里必须明确支持：

- Chat Completions
- Embeddings
- OpenAI-compatible base URL
- 可用的聊天模型名
- 可用的 embedding 模型名

## SubAPI 当前问题记录

SubAPI 页面给出的示例是 Codex CLI 配置：

```toml
model_provider = "OpenAI"
model = "gpt-5.5"
review_model = "gpt-5.5"

[model_providers.OpenAI]
base_url = "https://www.subapi.org"
wire_api = "responses"
requires_openai_auth = true
```

关键点：

- `wire_api = "responses"` 表示这个示例面向 OpenAI Responses API。
- RAGFlow 当前 OpenAI-Compatible 页面更偏向 Chat Completions 与 Embeddings。
- `gpt` 不是模型名，而更可能是密钥分组或别名。
- 如果供应商不支持 `/v1/chat/completions` 和 `/v1/embeddings`，RAGFlow 里直接填写会失败。

## RAGFlow 页面配置顺序

1. 进入 `Settings > Model providers`。
2. 选择支持的供应商，或选择 `OpenAI-API-Compatible`。
3. 添加 Chat 模型。
4. 添加 Embedding 模型。
5. 进入 `Set default models`。
6. 设置默认 Chat 模型与默认 Embedding 模型。
7. 再创建数据集。
