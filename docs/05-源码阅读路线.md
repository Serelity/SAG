# 05 - 源码阅读路线

源码路径：

```text
G:\RAG\ragflow-main
```

原则：先读主线，再读细节；先读配置和入口，再读算法和优化。

## 第一条主线：Docker 启动

阅读顺序：

1. `docker/.env`
2. `docker/docker-compose.yml`
3. `docker/docker-compose-base.yml`
4. `docker/service_conf.yaml.template`
5. `docker/entrypoint.sh`

重点问题：

- 哪些服务由 Compose 启动？
- 哪些端口暴露到 Windows？
- 哪些配置从 `.env` 注入？
- RAGFlow 主容器启动时做了哪些初始化？

## 第二条主线：模型供应商配置

阅读顺序：

1. `api/apps/llm_app.py`
2. `api/db/services/tenant_llm_service.py`
3. `rag/llm/chat_model.py`
4. `rag/llm/embedding_model.py`
5. `conf/llm_factories.json`
6. `conf/models/openai.json`

重点问题：

- 前端添加模型供应商后，后端保存了哪些字段？
- `OpenAI-API-Compatible` 如何映射到内部模型工厂？
- Chat 模型最终调用哪个 SDK 方法？
- Embedding 模型最终调用哪个 SDK 方法？
- 为什么只有 Responses API 的供应商可能不能直接用？

## 第三条主线：知识库与文档

阅读顺序：

1. `api/apps`
2. `api/db/db_models.py`
3. `api/db/services`
4. `rag/app`
5. `rag/svr`

重点问题：

- 数据集、文档、Chunk 分别对应哪些表？
- 文件上传后保存在哪里？
- 文档解析任务如何创建？
- 任务状态如何更新？

## 第四条主线：文档解析

阅读顺序：

1. `deepdoc/parser`
2. `deepdoc/vision`
3. `deepdoc/server`
4. `rag/nlp`

重点问题：

- PDF、Word、Excel 等文件如何解析？
- OCR 和版面分析在哪里处理？
- 解析后的文本如何进入 Chunk 流程？

## 第五条主线：检索与生成

阅读顺序：

1. `rag/llm`
2. `rag/prompts`
3. `rag/advanced_rag`
4. `conf/*_mapping.json`

重点问题：

- 用户问题如何转成检索请求？
- 检索结果如何排序或重排？
- Prompt 如何组织上下文？
- 最终回答如何附带引用？

## 第六条主线：前端页面

阅读顺序：

1. `web/package.json`
2. `web/src`
3. 前端 API 请求封装
4. 登录、模型供应商、知识库、聊天页面

重点问题：

- 前端如何组织路由？
- 前端如何保存登录态？
- 模型供应商页面如何提交配置？
- 数据集页面如何发起文档解析？
