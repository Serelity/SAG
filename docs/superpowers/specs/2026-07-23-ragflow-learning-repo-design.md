# RAGFlow 学习仓库设计

## 目标

建立一个适合上传到 GitHub 的个人学习仓库，用于记录 RAGFlow `v0.26.4` 的部署、排障、源码阅读路线、12 周学习计划和实验记录。

## 范围

本仓库保存学习文档，不复制完整上游源码，不保存本地运行数据，不保存任何 API Key、密码、Cookie 或 Token。

## 目录设计

```text

├── README.md

│   └── 05-源码阅读路线.md
├── labs/

│   └── week-01.md
└── notes/
    └── README.md
```

## 设计决策

### 不复制 RAGFlow 源码

原因：

- 上游项目体积较大。
- 学习仓库重点是记录个人学习过程。
- 直接复制源码容易混入运行数据或敏感配置。
- 后续如果需要基于源码修改，应单独 fork 上游仓库或创建开发分支。

### 文档全部使用中文

用户明确要求中文说明，因此 README、部署记录、排障记录、学习计划均使用中文。

### 保留模型配置问题记录

当前没有合适 LLM API 可用。仓库中记录 SubAPI 与 RAGFlow 当前 OpenAI-Compatible 调用方式之间的差异，作为后续源码学习和模型接入实验的入口。

### 先支持学习，不强依赖完整 RAG 闭环

没有 LLM API 时，仍可继续学习：

- Docker 服务组成。
- 配置文件。
- 后端 API。
- 数据库模型。
- 模型供应商源码。

完整文档向量化和知识库问答放到第 9-10 周。

## 验证方式

- 检查 Git 工作区中不包含 `.env`、密钥或运行数据。
- 检查 Markdown 文件可读。
- 完成本地 Git 提交。
- 上传 GitHub 前确认远程仓库地址。
